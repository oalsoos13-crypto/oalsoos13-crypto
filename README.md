# UDC · Debit Note System — نظام إشعارات الخصم

نظام متعدّد المستخدمين لإدارة الميزانية التسويقية وإصدار **إشعارات الخصم (Debit Notes)**
للجمعيات التعاونية — **الشركة المتحدة المتميزة للتجارة العامة للمواد الغذائية (UDC)**.

> **v2** — تحوّل النظام من نموذج أوّلي بملف HTML واحد يخزّن في المتصفّح، إلى تطبيق
> **full‑stack** حقيقي: خادم Node.js + قاعدة بيانات SQLite + مصادقة حقيقية + **سجل تدقيق
> كامل (Audit Trail)**، مع الحفاظ على نفس الواجهة العربية وتدفّق العمل.

A multi‑user application to manage the marketing budget and issue **debit notes**
to co‑operatives for **United Distinctive Co. for General Trading in Foodstuffs (UDC)**.

## نظرة عامة · Overview

- **الواجهة:** صفحة واحدة (SPA) عربية RTL ثنائية اللغة (ع/EN)، بدون أي مكتبات خارجية.
- **الخادم:** Node.js + Express.
- **قاعدة البيانات:** SQLite (ملف واحد، وضع WAL، معاملات ذرية) — بدون إعداد خادم قاعدة بيانات.
- **المصادقة:** كلمات مرور مُجزّأة بـ bcrypt + جلسات JWT (Header أو Cookie httpOnly).
- **التدقيق:** كل عملية تُسجَّل في جدول `audit_log` غير قابل للتعديل (مُلحَق فقط).

جميع بيانات العمل تُخزَّن على الخادم — لا شيء حسّاس في المتصفّح (فقط رمز الجلسة وتفضيل اللغة)،
فيعمل جميع المستخدمين على **نفس البيانات المشتركة** لحظيًّا.

## تدفّق العمل · Workflow

```
الماركتينج            مدير القسم           السوبر فايزر          المندوب
(Marketing)          (Division)           (Supervisor)         (Salesman)
    │                    │                     │                    │
 إنشاء الميزانية    توزيع ميزانية        توزيع الحصص على        إنشاء الكتب
 وتوزيعها على   →   الجمعيات على     →   المناديب ومتابعة   →   وإصدار إشعارات
 القنوات            المشرفين              الجمعيات               الخصم
                                                                   │
                                             ┌─────────────────────┘
                                             ▼
                              اعتماد بمستويين:  المشرف → مدير القسم
                              (pending_sup → pending_mgr → approved)
                                             │
                                             ▼
                                    التوثيق والتتبّع (Doc)
                              أرشفة + تقارير + سجل تدقيق + تصدير
```

الإشعار المرفوض **لا يُحذف**؛ يُحفظ مع **سبب الرفض وهوية الرافض والمرحلة**، ويعود الكتاب
إلى حالة "بانتظار" ليعيد المندوب إصدار الإشعار.

## الميزات · Features

**للعمل (Operations)**
- ميزانيات بفترات زمنية (اليوم/الأسبوع/الشهر/الربع/السنة أو مدى مخصّص).
- توزيع الميزانية على القنوات (الجمعيات/الأسواق/البقالات/الأونلاين).
- توزيع على المشرفين والمناديب مع حساب الحصص من **WOB** (Weight of Business) أو يدويًّا.
- أنواع كتب: Listing / Stand / Pallet / Price Off / CDA (نسبة أو ثابت).
- **قيمة الكتاب تُحسب في الخادم** (لا يمكن التلاعب بها من المتصفّح).
- ترقيم مستندات ذرّي متسلسل بلا فجوات: `LYSAL/<n>/<year>`.
- مستندات رسمية جاهزة للطباعة (letterhead + توقيع + بيانات الشركة).
- مرفقات للإشعارات (صور/PDF).

**للتدقيق والمراجعة (Audit)**
- **سجل تدقيق كامل** لكل عملية: مَن، متى، ماذا، والتفاصيل + IP.
- **هوية ووقت المعتمِد** على كل إشعار في كل مستوى (مشرف/مدير) + مسار اعتماد مرئي.
- حفظ المرفوض مع السبب والرافض والمرحلة.
- **تصدير CSV** (إشعارات/كتب/سجل التدقيق) بترميز UTF‑8‑BOM يدعم العربية في Excel.
- **نسخ احتياطي/استعادة** لكامل بيانات العمل (JSON).
- إدارة مستخدمين (إنشاء/تعديل/تعطيل/إعادة تعيين كلمة مرور).

**البيانات المرجعية (من COOPS_DETAILS)**
- **108 منفذ (outlet)** فعلي بأكواد CUST ID/PF، تابعة للجمعيات الأُم، مع FSM/مندوب/مندّب وخطوط السير.
- **عقود** لكل منفذ (%، lumsum، bonus، slap) وحضور الفئات (Lays/IEC/GONDOLA).
- **مبيعات سنوية 2015–2026 + تارجت + حالة LISTING** لكل جمعية أُم.
- شاشتان: «المنافذ والعقود» (لكل الأدوار — مرجع) و«المبيعات والتارجت» (للإدارة والتوثيق).

**عامة**
- تصميم متجاوب للموبايل، ثنائي اللغة، فرض تغيير كلمة المرور الافتراضية عند أول دخول.

## التشغيل السريع · Quick start

المتطلّبات: **Node.js 18+**.

```bash
git clone <repo-url>
cd oalsoos13-crypto
npm install
cp .env.example .env      # عدّل JWT_SECRET وكلمات المرور الافتراضية
npm start                 # يهيّئ قاعدة البيانات ويزرع البيانات تلقائيًّا
```

ثم افتح: `http://localhost:3000`

- تُهيّأ قاعدة البيانات وتُزرع البيانات المرجعية والمستخدمون تلقائيًّا عند أول تشغيل.
- **كل المستخدمين يجب أن يغيّروا كلمة المرور عند أول دخول.**
- كلمات المرور الافتراضية تُضبط عبر `DEFAULT_PASSWORD` و`ADMIN_PASSWORD` في `.env`.

حساب المدير الافتراضي: `admin`. (بقية المستخدمين مزروعون من فريق UDC — راجع `server/seed-data.js`.)

## النشر · Deployment

للحصول على **لينك عام** انشر النظام على استضافة تشغّل Node. يوجد `render.yaml`
(Blueprint لـ Render.com) و`Dockerfile` جاهزان. الخطوات الكاملة في
**[docs/DEPLOY.md](docs/DEPLOY.md)**.

## الإعداد للإنتاج · Production

1. اضبط في `.env`:
   - `NODE_ENV=production`
   - `JWT_SECRET` = سلسلة عشوائية طويلة — يرفض النظام الإقلاع في الإنتاج إن بقيت الافتراضية.
     ```bash
     node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
     ```
   - `DEFAULT_PASSWORD` / `ADMIN_PASSWORD` بكلمات قوية.
2. شغّل خلف بروكسي HTTPS (Nginx/Caddy) — الكوكي تُرسل `Secure` تلقائيًّا في الإنتاج.
3. خذ نسخًا احتياطية دورية لملف قاعدة البيانات `DB_FILE` (افتراضيًّا `./data/udc.db`)،
   أو استخدم زر «تنزيل نسخة احتياطية» في واجهة المدير.
4. للتشغيل الدائم استخدم مدير عمليات (systemd / pm2 / Docker).

## الأدوار والصلاحيات · Roles

| الدور | يستطيع |
|------|--------|
| `admin` | كل شيء + إدارة المستخدمين + النسخ/الاستعادة + سجل التدقيق |
| `marketing` | إنشاء/حذف الميزانيات + توزيع القنوات |
| `division` | توزيع الجمعيات على المشرفين + **اعتماد المدير** (المستوى الثاني) |
| `supervisor` | **اعتماد المشرف** (المستوى الأول) لمناديبه فقط |
| `salesman` | إنشاء الكتب + إصدار إشعارات الخصم (باسمه فقط) |
| `doc` | التوثيق والتتبّع + سجل التدقيق + التصدير (قراءة فقط) |

الصلاحيات مُطبّقة على **الخادم** لكل مسار — لا يكفي إخفاء الأزرار في الواجهة.

## الأمان · Security

- كلمات المرور مُجزّأة بـ bcrypt (لا تُخزّن أبدًا كنص).
- JWT موقّع بـ `JWT_SECRET`؛ صلاحية افتراضية 12 ساعة.
- فرض تغيير كلمة المرور الافتراضية عند أول دخول.
- رؤوس أمان أساسية (`X‑Content‑Type‑Options`, `X‑Frame‑Options`, `Referrer‑Policy`).
- التحقّق من الصلاحيات في الخادم لكل عملية، مع تحجيم اعتماد المشرف على مناديبه فقط.
- لا يمكن تعطيل/تنزيل آخر حساب مدير نظام.

> ملاحظة: لا تُودِع ملف `.env` أو `data/` في المستودع (مستثناة في `.gitignore`).
